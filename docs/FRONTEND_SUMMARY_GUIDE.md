## Overview

The Patient Summary API provides AI-generated and manually-edited summaries for the pre-visit huddle workflow. This guide shows **working code patterns** copied directly from our production E2E tests.

**Key Points**:
- Summaries are automatically generated by AI when clinical notes are created
- AI generation takes **~10 seconds** (LLM processing + Cloud Tasks delivery)
- Frontend must **poll** after note creation to retrieve AI summaries
- Manual summaries can be created/edited instantly

---

## API Endpoints Quick Reference

| Endpoint | Method | Auth | Description |
|----------|--------|------|-------------|
| `/api/v1/patients/{id}/summary` | GET | Bearer or API Key | Get latest summary |
| `/api/v1/patients/{id}/summary` | PUT | Bearer Token | Create/update manual summary |
| `/api/v1/patients/{id}/summary/history` | GET | Bearer or API Key | Get version history |

## 1. Get Patient Summary

Retrieve the most recent summary for a patient. Returns `404` if no summary exists yet.

### TypeScript Example

```typescript
interface PatientSummaryContent {
  summary_markdown: string;      // AI-generated markdown narrative
  chief_concerns?: string[];
  ongoing_treatment?: string;
  key_clinical_findings?: string[];
  action_items?: string[];
  risk_factors?: string[];
  allergies?: string[];
}

interface PatientSummary {
  id: string;
  patient_id: string;
  content: PatientSummaryContent;
  source: "AI" | "MANUAL";
  model_name: string | null;      // "gpt-4o-mini" for AI summaries
  model_provider: string | null;  // "openai" for AI summaries
  prompt_version: string | null;  // "v2" current version
  confidence_score: number | null; // 0.0-1.0 for AI summaries
  created_at: string;
  edited_by: string | null;       // User email for MANUAL edits
}

async function getPatientSummary(patientId: string, token: string): Promise<PatientSummary | null> {
  const response = await fetch(
    `${BASE_URL}/api/v1/patients/${patientId}/summary`,
    {
      headers: {
        "Authorization": `Bearer ${token}`,
        "Content-Type": "application/json"
      }
    }
  );
  
  if (response.status === 404) {
    // No summary exists yet - this is normal for new patients
    return null;
  }
  
  if (!response.ok) {
    throw new Error(`Failed to get summary: ${response.status}`);
  }
  
  return response.json();
}
```

### React Hook Example

```typescript
function usePatientSummary(patientId: string | null) {
  const [summary, setSummary] = useState<PatientSummary | null>(null);
  const [loading, setLoading] = useState(false);
  const [error, setError] = useState<string | null>(null);
  const { token } = useAuth();

  useEffect(() => {
    if (!patientId || !token) return;
    
    const fetchSummary = async () => {
      setLoading(true);
      setError(null);
      
      try {
        const response = await fetch(
          `${API_BASE}/api/v1/patients/${patientId}/summary`,
          { headers: { "Authorization": `Bearer ${token}` } }
        );
        
        if (response.status === 404) {
          setSummary(null);  // No summary yet
        } else if (response.ok) {
          setSummary(await response.json());
        } else {
          setError(`HTTP ${response.status}`);
        }
      } catch (err) {
        setError(err.message);
      } finally {
        setLoading(false);
      }
    };
    
    fetchSummary();
  }, [patientId, token]);

  return { summary, loading, error, refetch: () => { /* trigger useEffect */ } };
}
```

## 2. Create/Update Manual Summary

Use `PUT` to create or update a manual summary. This is used when a dentist wants to write their own summary.

### Request Schema

```typescript
interface UpdateSummaryRequest {
  content: {
    chief_concerns?: string[];
    ongoing_treatment?: string;
    allergies?: string[];
    key_clinical_findings?: string[];
    action_items?: string[];
    risk_factors?: string[];
    // Any custom fields are allowed
  };
}
```

### Working Example (from E2E tests)

```typescript
// Create initial manual summary
async function createManualSummary(patientId: string, token: string) {
  const response = await fetch(
    `${BASE_URL}/api/v1/patients/${patientId}/summary`,
    {
      method: "PUT",
      headers: {
        "Authorization": `Bearer ${token}`,
        "Content-Type": "application/json"
      },
      body: JSON.stringify({
        content: {
          chief_concerns: ["Test concern"],
          ongoing_treatment: "E2E test manual summary",
          allergies: ["Penicillin"]
        }
      })
    }
  );
  
  if (!response.ok) {
    throw new Error(`Failed to create summary: ${response.status}`);
  }
  
  const data = await response.json();
  // data.source will be "MANUAL"
  // data.edited_by will be the current user's email
  return data;
}

// Update existing summary
async function updateSummary(patientId: string, token: string) {
  const response = await fetch(
    `${BASE_URL}/api/v1/patients/${patientId}/summary`,
    {
      method: "PUT",
      headers: {
        "Authorization": `Bearer ${token}`,
        "Content-Type": "application/json"
      },
      body: JSON.stringify({
        content: {
          chief_concerns: ["Updated concern"],
          ongoing_treatment: "Updated by E2E test",
          allergies: ["Penicillin", "Latex"]  // Added new allergy
        }
      })
    }
  );
  
  return response.json();
}
```

> **Important**: PUT always requires a Bearer token (user must be logged in). API keys are not allowed for write operations.

## 3. Get Summary History

Retrieve all previous versions of summaries for a patient.

```typescript
interface SummaryHistoryResponse {
  items: PatientSummary[];
  total: number;
}

async function getSummaryHistory(
  patientId: string, 
  token: string,
  limit: number = 10,
  offset: number = 0
): Promise<SummaryHistoryResponse> {
  const response = await fetch(
    `${BASE_URL}/api/v1/patients/${patientId}/summary/history?limit=${limit}&offset=${offset}`,
    {
      headers: { "Authorization": `Bearer ${token}` }
    }
  );
  
  if (!response.ok) {
    throw new Error(`Failed to get history: ${response.status}`);
  }
  
  return response.json();
}
```

## 4. 🔥 AI Summary Polling Pattern (CRITICAL)

**This is where most frontend issues occur.** AI summaries are generated asynchronously when a clinical note is created. The generation takes **8-10 seconds**, so frontend must poll.

### The Problem

```
1. User creates clinical note → POST /notes returns 200 immediately
2. Backend triggers Cloud Tasks → starts AI generation
3. AI generates summary → ~10 seconds
4. Frontend polls GET /summary → initially returns 404
5. After ~10s → returns 200 with AI summary
```

### Working Polling Pattern (from E2E tests)

```typescript
const MAX_RETRIES = 15;       // Total retries
const RETRY_DELAY_MS = 2000;  // 2 seconds between retries
// Total max wait: 15 × 2s = 30 seconds

async function waitForAISummary(
  patientId: string,
  token: string,
  onProgress?: (attempt: number, maxRetries: number) => void
): Promise<PatientSummary | null> {
  
  for (let attempt = 0; attempt < MAX_RETRIES; attempt++) {
    const response = await fetch(
      `${BASE_URL}/api/v1/patients/${patientId}/summary`,
      { headers: { "Authorization": `Bearer ${token}` } }
    );
    
    if (response.status === 200) {
      const summary = await response.json();
      // Verify it's an AI summary (not a stale manual one)
      if (summary.source === "AI") {
        console.log(`✅ AI summary generated after ${attempt + 1} attempts`);
        return summary;
      }
    }
    
    if (response.status === 404 && attempt < MAX_RETRIES - 1) {
      onProgress?.(attempt + 1, MAX_RETRIES);
      await new Promise(resolve => setTimeout(resolve, RETRY_DELAY_MS));
    }
  }
  
  console.warn("⚠️ AI summary not generated within timeout");
  return null;
}
```

### React Component Example

```tsx
function PatientSummaryPanel({ patientId }: { patientId: string }) {
  const [summary, setSummary] = useState<PatientSummary | null>(null);
  const [isPolling, setIsPolling] = useState(false);
  const [pollProgress, setPollProgress] = useState("");
  const { token } = useAuth();

  // Initial fetch
  useEffect(() => {
    if (!patientId || !token) return;
    
    fetch(`${API_BASE}/api/v1/patients/${patientId}/summary`, {
      headers: { "Authorization": `Bearer ${token}` }
    })
      .then(res => res.ok ? res.json() : null)
      .then(setSummary);
  }, [patientId, token]);

  // Called after creating a note
  async function onNoteCreated() {
    setIsPolling(true);
    setPollProgress("Generating AI summary...");
    
    const aiSummary = await waitForAISummary(
      patientId,
      token,
      (attempt, max) => setPollProgress(`Waiting... (${attempt}/${max})`)
    );
    
    if (aiSummary) {
      setSummary(aiSummary);
      setPollProgress("");
    } else {
      setPollProgress("Summary generation timed out. Please refresh.");
    }
    setIsPolling(false);
  }

  if (!summary) {
    return (
      <div className="summary-empty">
        {isPolling ? (
          <Spinner label={pollProgress} />
        ) : (
          <p>No summary available. Create a clinical note to generate one.</p>
        )}
      </div>
    );
  }

  return (
    <div className="summary-panel">
      <div className="summary-header">
        <span className={`badge ${summary.source === "AI" ? "ai" : "manual"}`}>
          {summary.source === "AI" ? `🤖 ${summary.model_name}` : "✏️ Manual"}
        </span>
        <time>{new Date(summary.created_at).toLocaleString()}</time>
      </div>
      
      {summary.content.summary_markdown ? (
        <div 
          className="summary-content markdown"
          dangerouslySetInnerHTML={{ 
            __html: markdownToHtml(summary.content.summary_markdown) 
          }}
        />
      ) : (
        <div className="summary-content structured">
          {summary.content.chief_concerns?.map(c => (
            <p key={c}>• {c}</p>
          ))}
        </div>
      )}
    </div>
  );
}
```

## 5. Rendering AI Summary Markdown

AI summaries return markdown in `content.summary_markdown`. The format follows the "Pre-Visit Huddle" template:

```markdown
## 60-second snapshot
- Reason for visit / chief concern: Upper right molar sensitivity.
- Key history relevant to today: Symptoms started 2 weeks ago.
- Active problems: Tooth #14 shows distal caries.

## What changed since last visit
- New symptoms: None reported.
- New findings: Tooth #14 shows distal caries.

## Today's likely plan options
1) Excavate and restore tooth #14 with composite.
2) Schedule follow-up in 2 weeks.

## Questions to ask the patient
- How would you describe the sensitivity?
- Does the sensitivity occur with anything other than cold?
```

### Recommended Markdown Libraries

| Library | Notes |
|---------|-------|
| `react-markdown` | Safe, no XSS, supports custom components |
| `marked` + `DOMPurify` | Fast, but sanitize output! |
| `markdown-it` | Feature-rich, plugin ecosystem |

## 6. Common Issues & Solutions

### Issue: Always getting 404

**Cause**: Patient has no notes, or notes are older than 7 days.

**Solution**: Summaries are only generated when notes exist from the last 7 days.

### Issue: Summary generation times out

**Cause**: Cloud Tasks queue delay or LLM latency.

**Solution**: 
1. Increase polling time to 30+ seconds
2. Show clear "Generating..." UI to user
3. Check backend logs for errors

### Issue: 401 Unauthorized

**Cause**: Token expired or missing.

**Solution**: Refresh token before API call. Tokens expire after 8 days.

### Issue: 403 Forbidden on PUT

**Cause**: Using API key instead of Bearer token.

**Solution**: PUT requires Bearer token (logged-in user). Use:
```
Authorization: Bearer <jwt_token>
```
NOT:
```
X-Office-Key: sk_live_...
```

## 7. API Key vs Bearer Token

| Feature | Bearer Token | API Key (X-Office-Key) |
|---------|--------------|------------------------|
| GET summary | ✅ | ✅ |
| PUT summary | ✅ | ❌ (403) |
| GET history | ✅ | ✅ |
| Tracks `edited_by` | ✅ (user email) | N/A |
